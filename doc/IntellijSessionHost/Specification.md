# Reusable IntelliJ editor-area session host — specification

Status: **ready for planner; no implementation authorized**. Coordinator reviewed the draft and authorized the planner after the decisions below were recorded. Compatibility/attention assumptions remain subject to final contract/plan approval.
Source baseline: `ceee22659b1ecd84f18cf7c5ee07adc0edd05200` on `cheerful-silver-otter`.

## Goal

### Confirmed requirements and authority

- **R1 — Location and motivation:** reduce session-generated editor-tab clutter using a reusable **editor-area** host. Operator: “reusable editor-area host sounds good; run dev-process based on the investigation results”.
- **R2 — Workload and retention:** accommodate up to **twenty concurrent independent sessions**. Ordinary same-project presentation switching must not release, dispose, recreate or replay their retained consoles, nor lose terminal/user state.
- **R3 — Production replacement:** the operator subsequently selected **default production replacement**, not an opt-in prototype. Do not add a feature flag, dual presentation mode, off-mode or rollback-mode work. This is approval of the planning scope, not permission to implement it yet.
- **R4 — Activation semantics:** retain existing **explicit Enter/double-click Start/Resume for stopped rows**. Mere highlighting, keyboard browsing/multi-selection and editor restore/reopen never launch. Do not replace stopped-row activation with show-only semantics as an incidental refactor.
- **R5 — Comparison:** include exactly **one held different-session secondary view per owning project**. Primary selection switches independently. Selecting an already-held session focuses its existing pane; it does not steal/mirror the component. Closing the secondary view hides only that view. No same-session mirror or extra uncontrolled instances.
- **R6 — Return:** include a dedicated **in-memory previous-session A/B return action**. No persistent MRU list and no new default shortcut.
- **R7 — Preserve boundaries:** consolidate presentation, not processes, projects, worktrees, bridge credentials, remote lifetimes or existing cross-project/window routing.
- **R8 — Present authority:** specification → decision contract → bounded task/wave plan, followed by operator approval before implementation. This stage authorizes no source/test edits, builds, IDE/session actions, prototypes, commits, pushes or delegation.

R3–R6 were relayed as explicit operator decisions in the coordinator's blocking-review reply. The compatibility/continuity choices A1–A9 below were surfaced to the operator but were **not** reported as operator-selected. Keep that distinction in the contract/plan. Neither usability nor performance superiority is established by the investigation.

## Non-goals

- No implementation design, class hierarchy, extraction plan, patch, task ownership or dependency-wave design in this specification; these belong to subsequent stages.
- No competing tool-window host, twenty tool-window tabs, opt-in mode, dual production presentation, terminal engine replacement, shared emulator multiplexing, same-session mirrored consoles, process ownership change, background-terminal eviction/suspension, or general multi-project workspace virtualization.
- No implicit Start/Resume, Stop, Forget, Done, project opening or project transfer merely to switch an already-hosted session in the same project. Existing explicit stopped-row activation still launches under existing guards. Existing explicit cross-project navigation may still open/raise the destination project; it is not an ordinary same-project switch.
- No promise that the editor host remains visible while code occupies its editor group. No automatic code split, new default keyboard binding, persistent MRU history or unrelated navigator redesign is implied.
- No arbitrary speed/memory target, claim of twenty-session runtime success, provider state-retention success, or usability improvement based only on source feasibility.
- No knowledgebase/frozen-investigation edits. Preserve both existing untracked research deliverables unchanged.

## Risks

- **Production migration breadth:** default replacement, retained explicit stopped-row activation, comparison and previous-session return are all in scope. Legacy compatibility cannot be deferred behind a flag or hidden in an opt-in validation task. Final implementation approval is still required.
- **Usability remains hypothetical:** fewer documents can worsen discovery, A/B return, wrong-session input or code/console return, especially with duplicate titles, filters and twenty sessions. Research did not measure these outcomes.
- **Terminal state/focus:** retaining object identity does not prove hidden-layout, IME, fullscreen, scroll/search/selection or resize correctness. Empirical tests must remain explicit gates, not assumptions.
- **Editor-coupled consumers:** attention, header/context actions, notification routing, stale asynchronous facts and selection synchronization may become wrong-session operations when a file stops identifying one session.
- **Comparison/restoration:** ownership mistakes can steal a Swing component; legacy workspace restoration can reopen twenty views, lose selection or race duplicate restore owners. Cross-project recreation remains a different transition. Proposed compatibility/attention assumptions require final approval and should be visible in the contract.
- **Lifecycle/resources:** keeping hidden consoles retains their processing and memory costs. Hidden exits and project disposal must not drop readable stopped output or strand owned processes/listeners. No memory/CPU improvement is promised.
- **Reviewability and verification cost:** oversized TaskTreePanel plus integration with restore/attention/actions can conceal a broad refactor; the bounded task plan must expose that work and manual provider/IME checks. Two additional oversized files are flagged above, not proposed edit targets.

### Assumed defaults — reviewable at final contract/plan approval

- **A1 — assumed: per owning IntelliJ project, not one global host.** Reuse within existing ownership/window routing; do not pull project-owned sessions into a different project simply because the navigator is global. This continuity default was surfaced to the operator, not reported as operator-selected.
- **A2 — assumed: preserve browsing apart from explicit activation.** Keep existing filter/multi-select gestures and identity by stable session ID; no highlight-triggered launch or terminal-focus transfer. The explicit stopped activation behavior itself is confirmed R4, not an assumption.
- **A3 — assumed: primary presentation close is hide-only.** Closing primary does not Stop, Forget or Done; retain same-process console state while its project remains open. Secondary hide-only is confirmed R5. Preserve existing explicit lifecycle commands, project-close questions and remote close/quit behavior. Do not automatically choose another input session when the current one disappears.
- **A4 — assumed: no automatic takeover.** Background output, attention and metadata never select a different session, change the user's filter or take typing focus. Explicit launch/notification actions may focus their named target under existing guards; stale completions may not steal focus after the user moves on.
- **A5 — assumed: no unrelated presentation migration.** Keep existing navigation filtering/multi-select and lifecycle/action availability unless a confirmed decision explicitly changes them. All-session completeness and truthful identity are required outcomes; exact navigator UI is a later design choice.
- **A6 — assumed: empirical acceptance, no invented performance SLA.** Measure/report twenty-session behavior under comparable output, large/ordinary window conditions and providers actually in use; zero wrong-session input, involuntary launch/navigation and required-state loss are safety gates. Operator usability sign-off, not unmeasured timing claims, determines acceptance. In-process state retention is required; restart and actual cross-project moves are not promises of scroll/draft/IME persistence.
- **A7 — assumed: nonlaunching, bounded compatibility.** Remember last shown session for reopen/restore without auto-launch/reattach or displacing selected code. Consolidate twenty legacy session URLs into the bounded production presentation, preserve session/catalog data and the one restore-owner invariant, and show honest unavailable/no-selection state for missing IDs with no arbitrary input-target fallback. Remote liveness and transcript availability follow existing policy. This default was surfaced to the operator, not reported as operator-selected. No off-mode is requested.
- **A8 — assumed: previous-session return is presentation navigation.** Count intentional session activations, not row-highlight browsing, code selection or background events, for in-memory A/B return. Return focuses an already-held session in its existing pane. For a stopped prior target, show without implicitly Start/Resume; a missing target is unavailable rather than an arbitrary replacement. These edge defaults are proposed for the decision contract to expose at final approval; they do not alter confirmed explicit Enter/double-click stopped-row activation. No restart persistence is implied for the previous-session target.
- **A9 — assumed: visibility-based attention continuity.** Actually visible primary/secondary session panes in the active IDE window count as viewed; code-replaced/hidden panes and hidden retained consoles do not. Explicit acknowledgement remains explicit. This default was surfaced to the operator, not reported as operator-selected; do not broaden it to all owned sessions.
