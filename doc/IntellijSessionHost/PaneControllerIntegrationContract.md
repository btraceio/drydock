# Pane and metadata controller integration

This settles the T9 audit's internal seams. The operator approved a real Project for every controller, one lazy metadata loader, a package-private real-loader factory seam, and retries on accepted intentional Show/focus/Previous. No feature, executor, persistence field, pane factory or cap exception is added.

## Project and construction

- Every controller retains a non-null real Project. Replace the pure State/Consumer constructor with a Project-bearing constructor; update the four existing fixture call sites and give manually constructed test controllers a real test lifetime. No project-less mode, default-project fallback or silently skipped ownership path.
- The declarative public Project constructor remains the production entry. Package-private composition may accept State, selection publisher and `Function<Consumer<SessionFactsLoader.Result>, SessionFactsLoader>`; the normal value calls the actual `forProject(project, plugin, listener)`.
- Create at most one loader, lazily at the first permitted facts selection. Resolving an empty controller/service or adopting its workspace hint does not create panes, start metadata probes or touch plugin readiness merely for a fixture. The factory captures the Project but resolves the plugin when actually invoked.
- `paneFor(id)` directly constructs `new SessionPane(project, id, this)` and caches it per project. No pane factory indirection. Retain root and borrowed console identity across slot changes/hide/reopen; no registry release/move/start or transcript replay on a switch.

## Host and lease

- Implement every Host operation with real behavior. Facts read the controller's actual latest-result state, initially empty; never fabricate a domain session or install a default/no-op Host path.
- Deliberate valid pane focus follows the existing `focus(id)` authority, including its current/history/workspace/event rules. The Host notification must first validate that its ID is both retained and in the current primary/held slots. An invalid/off-slot notification is stale input, not a new explicit focus request: ignore it without changing epoch, permission, model, state or events. The explicit public/package focus operation retains its separate refused-request cancellation semantics. No empty callback or second model-only policy. A released/disposed attachment's queued focus cannot commit intent; caller/receiver attachment validity must be explicit.
- Strip events forward once to the immutable pane's real command entry; do not duplicate the shared lifecycle policy. Reject callbacks without a live lease or from anything other than the retained primary/held slot roots. Check the two slot identities in constant time, not an unbounded cache scan.
- Use the existing FileEditor identity lease: one owner, repeated acquisition by that owner is idempotent, a different owner is rejected, non-owner release has no effect. Owner release cancels pending focus, detaches the two mounted slot roots and clears the owner without disposing cached panes/consoles or changing history. A focused-pane query without a live attachment is empty. Do not reference the not-yet-defined concrete host editor.

## Selection and retry

- Cold pane metadata loads initially. An accepted intentional Show, focus or Previous targeting an already retained pane may select facts again: known answers stay cached by the loader, while FAILED/absent answers may retry.
- State-only requests for IDs without a retained pane start no metadata operation; visual creation supplies the cold path. A refused presentation does not probe. Resolve the actual accepted slot/explicit ID, never generic command targets from history alone.
- `Host.facts`, ordinary refresh, age ticks, result application and visibility changes do not select/retry or grant focus. Deliberate focus is not a metadata-generated focus notification.

## Keyed result delivery and progress

- Use the real loader with immutable `(id, generation, facts)` results. Its callback may be synchronous during select or arrive on any thread. Hop result application to the EDT and recheck controller/project/recipient lifetime, ID and generation there. Pass the same keyed result to its own cached pane; a hidden retained pane may update without selecting/reopening/focusing anything.
- Keep presentation state monotonic per ID: newer generations supersede older; a terminal answer may replace LOADING in the same generation; a duplicate terminal answer is idempotent, and late LOADING cannot replace that generation's terminal result. Generation0 is inert.
- The loader's success cache and the controller's latest presentation are distinct. Preserve actual returned LOADING/FAILED state (or equivalent pending state) so an ordinary refresh cannot repaint an older failure over a newer explicit retry. A known answer remains readable during catalog refresh as the loader specifies. No fabricated progress DTO or new probe from a getter.
- No callback mutates layout/history/workspace selection, opens the host or requests focus. Presentation focus epochs are not metadata result generations.

## Disposal and verification

- Claim disposal once using one authoritative closed state, also checked by resource creation and focus permission; include Project disposal. Do not introduce a gap between a separate atomic claim and a later boolean lifetime flag. Loader creation and the later loader-disposal handoff share this same closed state/coordination. Make rejection effective immediately, including callbacks already queued. Project disposal rejects use, but must not cause the first controller-owned cleanup to be skipped; only a previous controller disposal claim does that. Do not rely on an unverified platform guarantee that service disposal is on the EDT: keep required pane/root cleanup on the EDT, without a project-expiring condition that can discard the cleanup. Do not block the EDT waiting for background work.
- Dispose the one actual loader once; do not cancel shared initialization or stop the plugin executor. Detach/dispose pane presentation only, never borrowed terminal consoles. Release leases and controller-owned references/subscriptions through real lifecycle paths.
- Source guards for non-expiring cleanup inspect the cleanup scheduling path, not the entire controller. Result-delivery hops may correctly expire with the Project; the cleanup restriction must not forbid that later path.
- Tests inject only construction of the real SessionFactsLoader over controlled readiness/executors/probes, not replacement controller policy. Include the normal production factory path. Do not add a loader accessor or disposal counter only for tests.
- Exact-once ownership is established by the source guard/single disposal site plus runtime inert-after-dispose, idempotence and no-late-application checks. Report that this is not a runtime method-call count. Preserve actual callback-in-flight/queued UI tests and all prior controller cases.
- The measured pane draft is split into bounded T9 (three identity/registry/empty-cache cases) and test-only T41 (five lease/focus/strip/disposal cases); both finish before T40. Preserve a corrected complete eight-case snapshot and manifest before extraction; T41 restores that snapshot, not the weaker draft. T9 alone is not complete pane/lease acceptance.
- T40 additionally owns only the empty-cache test's staged expectation after cold `paneFor`: it changes from empty (T9 has no producer) to the real returned presentation being present once T40 wires selection. Initial and state-only-without-pane emptiness stay asserted. No unrelated test changes are authorized by that migration.
- Keep every stage under the unchanged 360-line bound. T40's old thin estimate is superseded by the measured T40/T42 split (293/184) and source-matched coordinator authorization. T40 is only the lazy/synchronous-result/monotonic-production substage; T42 restores retry/in-flight/disposal/production-path cases before UI/events. Every test wait, including probe-arrival checks under mutations, has a bounded deadline and explicit failure. A cancelled mutation or uncompiled correction is never reported as passed coverage. A pane/lease substage is not complete metadata or host delivery; loader/receiver tests must finish before the dependent UI/event integration. Recount actual code and fixture/lifetime changes, including the existing tests newly owned for constructor migration.
