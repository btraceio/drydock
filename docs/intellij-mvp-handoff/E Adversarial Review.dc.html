Adversarial review of E for MVP

An IntelliJ-UX reviewer's pass over E, looking for what breaks under real use. It was written by the same model that drew E, so treat it as a checklist, not an independent sign-off. Each item has the frames it affects, the failure, and a proposed fix. Items marked DECIDE need your call.

High: likely to hurt in week one

H1 · Keystrokes the agent needs get eaten by the IDEE1, E4, E9
Agent TUIs live on Esc (interrupt), Shift+Tab (mode), ⌃C, ⌃R and arrow history. In an editor tab, the IDE keymap and editor actions see those keys first. A swallowed Esc means the user can't stop a runaway agent from the place they're looking at it. My own ⌃⇧A / ⌃⇧R shortcuts add more conflicts. Fix: add a pass-through key list to the Phase 0 editor spike as a pass/fail gate, test it with all three agents, and give Drydock shortcuts only actions that don't fire while the agent tab has focus.
H2 · ⌘Q silently kills every working agentDECIDED · confirmE6
"Window close stops, no prompt" was set for one window. Quitting the IDE closes all of them, and an agent mid-edit or mid-test leaves a half-applied change. A balloon afterwards doesn't undo that. Fix: keep "no prompt" for idle and at-prompt agents. Confirm only when ≥1 agent is working: "Stop 2 working agents?" with Stop / Cancel / Don't ask again. That's one dialog in the rare dangerous case.
H3 · Committing from the wrong scopeDECIDED · proposalR2, E7
R2 reuses the Commit view, where checkboxes mean "include in commit". In "branch vs main" scope the tree lists files that are already committed, still next to checkboxes and a Commit button. Users will read it as "commit these 4 files". Fix: in branch scope, hide the checkboxes and swap Commit for Finish ▾. Show a one-line hint ("Reviewing 3 commits + 1 uncommitted file vs main") so the scope is always named. Uncommitted files keep a ● marker.
H4 · A new window is slow before it's usefulE3
Each worktree is a new Project: Gradle/Maven import and indexing on a fresh copy of dd-trace-java takes minutes and memory. If the agent waits for the window to be "ready", the main promise (start a task fast) breaks. If it doesn't, the user sees a red, half-indexed project. Fix: start the agent as soon as the frame exists, and say so in the strip ("Working · IDE still indexing"). Offer shared indexes and "skip build import" in the New Agent Worktree dialog. Measure on dd-trace-java before MVP.
H5 · You and the agent editing the same fileE4, E10
The split-editor story (E4) invites typing in the file the agent is changing. Unsaved buffer vs on-disk write gives you IntelliJ's "file changed on disk" conflict, or silently lost keystrokes. "Writes + Here" on the main checkout makes it a daily event. Fix: while an agent is working, mark the files it has touched this turn as read-only in the editor (a soft lock with an "Edit anyway" banner), and flush unsaved buffers before each agent turn. Keep "Writes + Here" behind Start anyway (already in E10).

Medium: friction and confusion

M1 · Four places list the same sessions Agents ▾, the status-bar widget, the Services node and the Welcome tab all show the same catalog. Each needs its own state syncing and its own bugs. The status widget mostly repeats the Agents ▾ counts. Fix: MVP ships Agents ▾ + Welcome tab only. Status widget and Services node come later, and only if users ask.
M2 · Window titles that rename themselves Agent-given titles arrive late and change, and two sessions can get near-identical titles. A window whose name shifts under ⌘` is hard to find again. Fix: window = repo · branch (stable, unique). The agent title lives on the tab and in Agents ▾ rows, where change is expected.
M3 · Attention you miss when the IDE isn't in front Balloons and badges only show in the focused IDE. With the browser in front, "needs you" can sit unnoticed for 20 minutes. With 4 agents in the IDE, balloons stack up. Fix: use the IDE's own system notification when the app is inactive, as it does for long builds. Collapse simultaneous balloons into one ("2 agents need you").
M4 · Merge into main touches your own checkout "Merge into main" runs in the main checkout, which may be dirty, on another branch, or open in a window you're editing. Fix: a pre-flight in the Finish menu ("main checkout has 2 uncommitted files: stash / cancel"), never a silent branch switch. Disable it with a reason when main isn't on the target branch.
M5 · Too many verbs that end a session Close tab, Stop, close window, Forget, Remove Worktree… Each does something different, and users won't keep them apart. Fix: a single "Done with this…" action that offers the combinations (as in B7), plus a tooltip on tab close: "Agent keeps running · ⌃⇧A to reopen".
M6 · Resume has a cost nobody sees Resuming a long conversation re-sends its context. The core already has ResumeCostEstimate, but E6's Resume button doesn't show it. Fix: show the estimate on the Resume button ("Resume · ~180k tokens"), and offer "Resume with summary" when the estimate is large.
M7 · The tour holds up the MVP T1 and T2 are both large and undecided. Shipping R2 with findings already covers "review the agent's diff". Fix: cut the tour from MVP. Run the T2 diff-viewer extension spike alongside, and decide T1/T2 from its result.

Low

  • Colour-only status. Blue vs amber dots are weak for colour-blind users. Pair them with shape (● working, ◐ needs you, ○ idle), as the title marker already does.
  • RO overstates safety. Even enforced read-only agents can run shell commands. Strip copy: "can't edit files" → "won't edit files (plan mode)".
  • Raising windows across macOS Spaces jumps the whole desktop when a worktree window is full-screen elsewhere. Raise should show which window it's going to.
  • Title-bar marker (E5 ③) needs internal API and is rarely visible in the New UI on macOS. Drop it from MVP.
