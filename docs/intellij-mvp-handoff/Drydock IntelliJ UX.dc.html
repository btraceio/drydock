Drydock in IntelliJ: where do sessions live?

v2 broke because one object stood for four different things: the durable session, the live agent process, its presentation (a Terminal tab) and the window (a Project). The four directions below keep those separate, and each gives them a different home in the IDE. All share a set of fixed rules, listed at the bottom.

Fixed in every direction

  • One IDE window per worktree. The catalog is app-level and visible from every window.
  • Clicking a session that lives elsewhere raises that window. Nothing is proxied.
  • IDE or Project open starts nothing. Resume starts exactly one execution.
  • Only Forget removes a row. Removing a worktree is a separate step that warns about data loss.
  • Stop is Drydock's own action (non-soft, then force-kill). There's no native Rerun.
  • Rows are labelled by the agent-given title. Agent and branch are secondary.
  • "Needs you" shows as a stripe badge, a balloon and a window-title marker.

Decisions these surface

  1. Should an agent keep working when its window, or the IDE, closes? D says yes; A, B and C say no.
  2. Branded surface (B) or IDE-native surfaces (A, C, D)?
  3. Where is the console most comfortable for long sessions: bottom panel (A, B, D) or editor (C)?
  4. Is the guided tour worth its own review tab (A, B, C), or is a decorated Changes view enough (D)?
