Services-native

Drydock contributes a node to the IDE's Services tool window, the way Docker, Databases and Run Dashboard do. The tree is app-level, so every window shows every repo › worktree › session. A session's console lives in the Services detail pane of the window that owns its worktree; in every other window the same node shows status and a Raise button.

Who owns what Durable sessionServices node (app catalog) Live processProcessHandler in the worktree Project PresentationServices detail pane › Console tab Windowone Project per worktree
Fits — tree already models parent › child facts; group-by, speed search, multi-select and keyboard nav come free; console-in-detail is how Docker shows logs.
Strains — Services is a shared, often-hidden window; console beside a tree is cramped at the bottom anchor; Drydock competes with run configs for the top level.
