Synthesis: agent in the editor

Built from your four answers. It uses the window model and editor-tab console from C and only IDE-native surfaces for the catalog: an Agents ▾ title-bar widget next to the Project widget, a status-bar widget, and an optional Services node from A. More than one session in a worktree

A window is still one worktree, but it can hold several agent tabs. A read-only session is the usual second one: ask questions, explore, plan, without creating a worktree. Sessions are created in a mode, Writes or Read-only, and the mode shows on the tab. Rule: at most one writing session per worktree by default; a second one needs an explicit override.

The guided tour gets its own editor

A step is a logical change: narrative, anchored line ranges with notes, impact, checks that gate it, and an optional staged diagram. A file can belong to several steps, so the tour can't be a grouping of the Changes tree. Both options open the tour as an editor tab next to the agent, reached from the agent strip's Review link or the Changes header. They differ in who renders the code.
