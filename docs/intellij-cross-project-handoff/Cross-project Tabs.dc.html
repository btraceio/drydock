Cross-project agent tabs
Run and talk to agents from other projects and worktrees without leaving this window. A hosted tab shows where it comes from, and anything that needs the full project (Changes, file links, Finish) opens the owning window, and the console follows. Based on the spike: the process belongs to the app and windows only display it.

The jump opens or raises the owning window and moves the session there: a new console in that window with the history replayed into it (spike variant b). The process isn't restarted. Its home tab is plain, with no chip.
The hosted tab closes and a balloon confirms the move. Bring back here moves it back. A session is shown in one window at a time. Showing it somewhere else moves it; it's never copied.
Timing from the spike: a warm jump to input takes about 10 ms. A cold one, when the window has to open, takes 2–5 s, so show the platform's open-project progress in the host while it opens.

Attention raises the window currently showing the session, and the balloon is labelled with the session's own repo · branch. If no window shows it, the balloon appears in the focused window with Show here.
Restart: hosted tabs aren't restored. Sessions come back as idle rows with Resume here. Their own windows restore their own tabs, as in the MVP.
Running elsewhere: clicking a row shown in another window raises that window (MVP fix 2). Show here in its context menu moves it.
Rules
1. The app owns the process. A window shows at most one console per session, and each session is shown in at most one window.
2. Anything that needs the project model (Changes, Finish, file navigation, run configurations) happens in the owning window. Hosted tabs link there, and the console moves with the jump.
3. Hosted sessions route IDE MCP calls to their own worktree (MVP fix 1). With no window open for it, those calls fail cleanly, and the agent uses Drydock's own usages tool, whose jdtls starts on its first query.
4. When a hosted agent's turn ends, Drydock refreshes any of its files open in this window. If its worktree folder disappears, the session is marked gone.
5. The one-writer-per-worktree rule is unchanged and doesn't depend on which window shows a session.
